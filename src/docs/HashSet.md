# HashSet과 hashCode 복습 노트

> 직접 만든 Set에 해시 구조를 적용하면서, `hashCode()`와 `equals()`가 왜 함께 필요한지 정리했다.  
> 전체 구현을 그대로 옮기지 않고 핵심 동작과 실패 사례만 남겼다.

---

## 1. 해시를 사용하는 Set의 기본 구조

Set은 같은 값을 중복해서 저장하지 않는다.

단순 리스트로 Set을 만들면 값을 추가할 때마다 전체 요소를 검색해야 한다.

해시를 이용하면 먼저 값의 해시 인덱스를 구하고, 해당 버킷만 확인할 수 있다.

```java
int index = hashIndex(value);
List<Integer> bucket = buckets[index];
```

추가 과정은 다음처럼 정리할 수 있다.

```text
if (bucket.contains(value)) {
    return false;
}

bucket.add(value);
return true;
```

같은 값이 이미 있으면 추가하지 않고, 없을 때만 저장한다.

---

## 2. 숫자만 처리하는 구현의 한계

숫자는 나머지 연산을 이용해 쉽게 인덱스로 바꿀 수 있다.

```java
int index = value % capacity;
```

하지만 문자열이나 직접 만든 객체는 그대로 배열 인덱스로 사용할 수 없다.

```text
"A"
Member("A")
```

해시 기반 자료구조가 다양한 타입을 받으려면, 모든 객체를 정수 값으로 바꿀 수 있는 공통 방법이 필요하다.

---

## 3. 해시 코드와 해시 인덱스는 다르다

해시 코드는 객체를 정수로 표현한 값이다.

```java
int hashCode = value.hashCode();
```

해시 인덱스는 이 해시 코드를 실제 배열 범위에 맞게 조정한 값이다.

```java
int index = Math.abs(hashCode) % capacity;
```

정리하면 다음 순서다.

```text
객체
→ hashCode()
→ 정수 해시 코드
→ 배열 크기에 맞게 계산
→ 해시 인덱스
```

해시 코드는 배열 크기보다 클 수도 있고 음수일 수도 있으므로, 그대로 배열 인덱스로 사용하지 않는다.

---

## 4. Java 객체가 `hashCode()`를 가질 수 있는 이유

모든 클래스는 `Object`를 상속하므로 `hashCode()` 메서드를 사용할 수 있다.

기본 구현은 서로 다른 인스턴스에 대해 서로 다른 값이 나올 수 있다.  
반면 `String`, `Integer` 같은 클래스는 내부 값을 기준으로 해시 코드를 계산하도록 재정의되어 있다.

```java
String a = new String("A");
String b = new String("A");
```

`a`와 `b`는 다른 인스턴스지만 문자열 내용이 같으므로 같은 값으로 비교되고, 해시 코드도 같은 기준으로 계산된다.

직접 만든 객체도 논리적으로 같은 기준을 정했다면 `hashCode()`를 그 기준에 맞게 재정의해야 한다.

---

## 5. 사용자 정의 객체에서 동등성 정하기

회원 객체를 `id`가 같으면 같은 회원으로 판단한다고 가정해 보자.

```java
class Member {
    private final String id;
}
```

이때 참조값이 아니라 `id`를 기준으로 비교하려면 `equals()`를 재정의해야 한다.

```java
@Override
public boolean equals(Object obj) {
    if (this == obj) {
        return true;
    }

    if (!(obj instanceof Member other)) {
        return false;
    }

    return Objects.equals(id, other.id);
}
```

해시 코드도 같은 기준을 사용한다.

```java
@Override
public int hashCode() {
    return Objects.hash(id);
}
```

내가 이해한 규칙은 다음과 같다.

> `equals()`에서 같다고 판단하는 두 객체는 같은 `hashCode()`를 반환해야 한다.

---

## 6. `hashCode()`와 `equals()`가 둘 다 없을 때

내용이 같은 객체 두 개를 만들어도 기본 비교는 서로 다른 인스턴스로 본다.

```java
Member a = new Member("A");
Member b = new Member("A");
```

두 메서드를 재정의하지 않으면 다음 문제가 생길 수 있다.

- 객체마다 해시 코드가 달라 다른 버킷에 저장된다.
- 참조값이 다르므로 같은 내용이어도 중복으로 판단하지 못한다.
- 같은 내용으로 새 객체를 만들어 검색해도 찾지 못할 수 있다.

즉, 객체의 실제 의미보다 인스턴스 자체를 기준으로 동작하게 된다.

---

## 7. `hashCode()`만 재정의했을 때

`id`가 같으면 같은 해시 코드를 반환하도록 만들었다고 가정해 보자.

그러면 같은 `id`를 가진 객체들은 같은 버킷으로 이동한다.

하지만 `equals()`가 기본 구현 그대로라면 버킷 안에서 서로 다른 객체로 판단한다.

결과적으로:

- 같은 버킷에는 들어간다.
- 중복 제거는 실패한다.
- 같은 내용의 새 객체로 검색해도 찾지 못한다.

해시 코드는 후보 버킷을 찾을 뿐이고, 최종적인 동일성 확인은 `equals()`가 담당한다.

---

## 8. `hashCode()`와 `equals()`를 함께 재정의했을 때

같은 `id`를 가진 객체는:

1. 같은 해시 코드를 얻는다.
2. 같은 버킷으로 이동한다.
3. `equals()` 비교에서 같은 값으로 판단된다.

따라서 중복 추가를 막을 수 있고, 같은 `id`를 가진 새 객체로도 검색할 수 있다.

```java
Member stored = new Member("A");
Member search = new Member("A");
```

두 객체의 참조는 달라도 논리적인 값이 같다면 Set에서는 같은 요소로 다룰 수 있다.

---

## 9. 해시 기반 Set의 주요 연산

### 추가

1. 해시 인덱스를 계산한다.
2. 해당 버킷에 같은 값이 있는지 확인한다.
3. 없으면 추가하고 크기를 증가시킨다.

### 검색

1. 검색 값의 해시 인덱스를 계산한다.
2. 해당 버킷에서 `equals()`로 값을 찾는다.

### 삭제

1. 해시 인덱스를 계산한다.
2. 해당 버킷에서 같은 값을 제거한다.
3. 실제로 제거됐다면 크기를 감소시킨다.

충돌이 적다면 각 버킷에 들어 있는 요소 수가 적기 때문에 평균적으로 빠르게 동작한다.

---

## 10. 단순 구현에서 확인한 한계

직접 만든 예제는 해시 구조의 원리를 이해하는 데 도움이 되지만 실제 구현에서는 더 고려할 점이 있다.

- 해시 코드가 음수일 수 있다.
- 값이 많아지면 충돌이 증가할 수 있다.
- 배열 크기를 언제 늘릴지 결정해야 한다.
- `null`을 허용할지 정해야 한다.
- `equals()`와 `hashCode()` 계약을 지키지 않으면 검색과 중복 제거가 깨질 수 있다.

직접 구현의 목적은 Java의 `HashSet`을 완전히 대신하는 것이 아니라, 내부 동작을 단계별로 이해하는 데 있다고 정리했다.

---

## 핵심 정리

- 해시 기반 Set은 값으로 버킷을 빠르게 찾는다.
- `hashCode()`는 객체를 정수 해시 코드로 바꾼다.
- 해시 인덱스는 해시 코드를 배열 범위에 맞게 계산한 값이다.
- 해시 코드는 후보 위치를 찾고, `equals()`는 실제 같은 값인지 판단한다.
- 논리적으로 같은 객체는 같은 해시 코드를 반환해야 한다.
- 사용자 정의 객체를 `HashSet`에 넣을 때는 `equals()`와 `hashCode()`를 함께 설계해야 한다.
- 충돌이 적을 때 추가, 검색, 삭제가 평균적으로 빠르게 동작한다.
