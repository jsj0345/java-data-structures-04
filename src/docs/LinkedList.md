# LinkedList 복습 노트

> 배열 기반 리스트의 한계를 확인한 뒤, 노드를 연결하는 방식이 어떤 차이를 만드는지 정리했다.  
> 전체 구현 코드를 옮기기보다 노드 구조와 연산 과정에 집중했다.

---

## 1. 배열 기반 리스트에서 불편했던 점

배열 리스트는 내부 배열에 요소를 연속해서 저장한다.

이 구조는 인덱스 조회에는 유리하지만, 앞이나 중간에 값을 추가하면 뒤쪽 요소를 이동해야 한다.

```text
[A, B, C, D]
```

`B` 앞에 `X`를 넣으려면 `B`, `C`, `D`를 뒤로 밀어야 한다.

삭제할 때도 빈칸을 없애기 위해 뒤 요소를 앞으로 당겨야 한다.

또한 내부 배열의 공간이 부족하면 더 큰 배열을 만들고 기존 값을 복사해야 한다.  
반대로 여유 공간을 넉넉하게 잡으면 사용하지 않는 칸이 남을 수 있다.

---

## 2. 노드로 데이터를 연결하는 방식

연결 리스트는 데이터를 배열의 연속된 칸에 넣지 않는다.  
대신 각 데이터를 노드에 담고, 다음 노드의 위치를 연결한다.

```java
class Node {
    Object item;
    Node next;
}
```

노드에는 두 정보가 있다.

- `item`: 현재 노드가 보관하는 값
- `next`: 다음 노드를 가리키는 참조

예를 들어 `A → B → C`는 다음처럼 연결된다.

```text
[A | next] → [B | next] → [C | null]
```

각 노드는 필요한 시점에 하나씩 생성할 수 있으므로, 배열처럼 큰 공간을 미리 준비할 필요가 없다.

---

## 3. 연결 리스트에서 값을 찾는 과정

연결 리스트에는 배열과 같은 인덱스 계산이 없다.

세 번째 요소를 찾고 싶어도 첫 번째 노드부터 `next`를 따라가야 한다.

```text
Node current = first;

while (current != null) {
    current = current.next;
}
```

따라서 특정 위치 조회는 앞에서부터 이동한 노드 수만큼 시간이 든다.

```text
인덱스 조회: O(n)
값 검색: O(n)
```

내가 이해한 가장 큰 차이는 다음과 같다.

> 배열은 위치 계산으로 이동하고, 연결 리스트는 참조를 따라 이동한다.

---

## 4. 앞쪽에 데이터를 추가하는 과정

첫 번째 노드를 가리키는 `first`가 있다고 가정해 보자.

```text
first → A → B → C
```

앞에 `X`를 추가하려면 새 노드가 기존 첫 노드를 가리키게 하고, `first`만 새 노드로 바꾸면 된다.

```text
first → X → A → B → C
```

개념적으로 필요한 작업은 두 가지다.

```text
newNode.next = first;
first = newNode;
```

기존 요소 전체를 이동하지 않아도 되므로 첫 위치 추가는 빠르게 처리할 수 있다.

```text
첫 위치 추가: O(1)
```

---

## 5. 중간 추가의 실제 비용

연결할 위치의 노드를 이미 알고 있다면 참조 몇 개만 바꾸면 된다.

```text
A → B → C
```

`B`와 `C` 사이에 `X`를 넣으면 다음처럼 연결을 변경한다.

```text
A → B → X → C
```

하지만 “2번 인덱스에 추가”처럼 위치만 전달받았다면 먼저 그 위치까지 노드를 찾아가야 한다.  
따라서 전체 비용은 위치 탐색 때문에 `O(n)`이 될 수 있다.

즉, 연결 자체는 빠르지만 위치를 찾는 시간은 별도로 필요하다.

---

## 6. 삭제도 연결 변경으로 처리한다

중간 노드를 삭제할 때는 이전 노드가 삭제 대상의 다음 노드를 가리키게 한다.

```text
A → B → C
```

`B`를 삭제하면:

```text
A ─────→ C
```

배열처럼 `C` 이후의 모든 데이터를 앞으로 옮길 필요는 없다.

다만 삭제할 노드 또는 그 이전 노드까지 찾는 과정이 필요하면 탐색 비용이 추가된다.

---

## 7. ArrayList와 LinkedList 비교

| 연산 | ArrayList | 단순 연결 리스트 |
|---|---:|---:|
| 인덱스 조회 | `O(1)` | `O(n)` |
| 값 검색 | `O(n)` | `O(n)` |
| 앞에 추가·삭제 | `O(n)` | `O(1)` |
| 중간 추가·삭제 | `O(n)` | 위치 탐색 포함 시 `O(n)` |
| 뒤에 추가 | 보통 `O(1)` | 마지막 노드 참조가 없다면 `O(n)` |

여기서 연결 리스트의 뒤쪽 추가 성능은 구현 방식에 따라 달라질 수 있다.  
첫 노드만 기억하는 단순 구현은 끝까지 이동해야 하지만, 마지막 노드를 따로 기억하는 구현은 이동 과정을 줄일 수 있다.

---

## 8. 연결 리스트의 장점과 한계

### 장점

- 필요한 만큼 노드를 만들 수 있다.
- 앞쪽 추가와 삭제에서 요소 전체를 이동하지 않는다.
- 연결 위치를 알고 있다면 참조 변경만으로 삽입·삭제가 가능하다.

### 한계

- 인덱스로 바로 접근할 수 없다.
- 원하는 위치까지 노드를 하나씩 따라가야 한다.
- 각 노드가 다음 노드 참조도 보관하므로 데이터 외의 정보가 추가된다.
- 연속된 배열처럼 단순한 메모리 구조는 아니다.

---

## 9. 내가 정리한 사용 기준

연결 리스트는 다음 상황을 생각해 볼 수 있다.

- 앞쪽에서 추가와 삭제가 자주 발생한다.
- 임의 위치 조회보다 연결 변경이 더 중요하다.
- 배열의 요소 이동 비용을 줄이고 싶다.

반대로 인덱스로 자주 조회하거나 대부분 데이터를 뒤에 추가하는 일반적인 목록이라면 배열 리스트가 더 단순할 수 있다.

---

## 핵심 정리

- 연결 리스트는 값과 다음 노드 참조를 가진 노드들의 연결로 구성된다.
- 인덱스 계산이 없으므로 위치 조회는 `O(n)`이다.
- 첫 위치 추가·삭제는 전체 요소를 이동하지 않아도 된다.
- 중간 삽입·삭제는 연결 변경 자체보다 위치 탐색 비용을 함께 봐야 한다.
- ArrayList와 LinkedList는 어느 쪽이 항상 더 좋은 것이 아니라, 자주 수행하는 연산에 따라 선택해야 한다.
