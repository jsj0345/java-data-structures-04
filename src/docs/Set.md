# Java Set 구현체 복습 노트

> `HashSet`, `LinkedHashSet`, `TreeSet`의 공통점과 차이를 사용 목적 중심으로 정리했다.  
> 구현체 이름만 외우기보다 “중복 제거 외에 어떤 순서가 필요한가”를 기준으로 비교했다.

---

## 1. Set의 공통 특징

`Set`은 같은 요소를 중복해서 저장하지 않는 컬렉션이다.

```text
Set<String> values = new HashSet<>();

values.add("A");
values.add("A");
```

같은 값인 `"A"`를 두 번 추가해도 Set 안에는 하나만 남는다.

Set을 사용할 때는 보통 다음 질문이 중요하다.

- 이미 같은 값이 들어 있는가
- 요소의 입력 순서를 유지해야 하는가
- 정렬된 순서가 필요한가

`Set` 자체는 중복 없는 집합이라는 규칙을 정의하고, 실제 저장 방식과 순서는 구현체가 결정한다.

---

## 2. 컬렉션 인터페이스 구조

Java 컬렉션의 공통 기능은 `Collection` 인터페이스에서 시작한다.

```text
Collection
├─ List
├─ Set
└─ Queue
```

`Set`은 `Collection`의 하위 인터페이스이며 중복을 허용하지 않는 규칙을 추가한다.

대표적인 구현체는 다음과 같다.

```text
Set
├─ HashSet
│  └─ LinkedHashSet
└─ TreeSet
```

`TreeSet`은 `HashSet`의 하위 클래스가 아니라 별도의 방식으로 `Set`을 구현한다.

---

## 3. HashSet

`HashSet`은 해시 자료구조를 사용한다.

### 특징

- 중복을 허용하지 않는다.
- 입력한 순서를 보장하지 않는다.
- 추가, 검색, 삭제가 평균적으로 빠르다.
- 요소의 존재 여부가 중요할 때 적합하다.

```text
Set<String> set = new HashSet<>();

set.add("C");
set.add("B");
set.add("A");
```

반복해서 읽을 때 `"C", "B", "A"` 순서로 나온다고 기대하면 안 된다.

### 사용하기 좋은 경우

- 회원 ID처럼 중복을 막아야 한다.
- 순서는 중요하지 않다.
- 포함 여부를 자주 확인한다.

---

## 4. LinkedHashSet

`LinkedHashSet`은 해시 구조를 사용하면서 요소의 연결 순서도 함께 관리한다.

### 특징

- 중복을 허용하지 않는다.
- 요소가 추가된 순서를 유지한다.
- 주요 연산은 평균적으로 빠르다.
- 순서를 관리하기 위한 정보가 추가로 필요하다.

```text
Set<String> set = new LinkedHashSet<>();

set.add("C");
set.add("B");
set.add("A");
```

반복 결과는 입력 순서와 같은 형태로 유지된다.

```text
C B A
```

### 사용하기 좋은 경우

- 중복은 제거해야 한다.
- 사용자가 입력한 순서도 유지해야 한다.
- 정렬이 아니라 “추가된 순서”가 중요하다.

---

## 5. TreeSet

`TreeSet`은 트리 기반 구조를 사용하며 요소를 정렬된 순서로 관리한다.

### 특징

- 중복을 허용하지 않는다.
- 입력 순서가 아니라 값의 정렬 순서를 유지한다.
- 주요 연산은 `O(log n)` 수준으로 동작한다.


```text
Set<String> set = new TreeSet<>();

set.add("C");
set.add("B");
set.add("A");
```

반복하면 값의 정렬 기준에 따라 다음처럼 나온다.

```text
A B C
```

### 사용하기 좋은 경우

- 중복을 제거하면서 정렬된 결과가 필요하다.
- 범위에 해당하는 값이나 순서상 가까운 값을 다루고 싶다.
- `HashSet`보다 느리더라도 정렬 상태가 중요하다.

---

## 6. 세 구현체 비교

| 구현체 | 중복 | 반복 순서 | 주요 연산 | 적합한 상황 |
|---|---|---|---:|---|
| `HashSet` | 허용 안 함 | 보장 안 함 | 평균 `O(1)` | 중복 제거와 빠른 검색 |
| `LinkedHashSet` | 허용 안 함 | 입력 순서 | 평균 `O(1)` | 입력 순서까지 유지 |
| `TreeSet` | 허용 안 함 | 정렬 순서 | `O(log n)` | 정렬된 집합이 필요함 |

내가 구분하는 기준은 다음과 같다.

```text
순서가 필요 없음
→ HashSet

추가한 순서가 필요함
→ LinkedHashSet

값의 정렬 순서가 필요함
→ TreeSet
```

---

## 7. 같은 코드에 구현체만 바꿔 보기

`Set` 타입으로 받으면 구현체를 바꾸면서 결과를 비교할 수 있다.

```java
private static void addValues(Set<String> set) {
    set.add("C");
    set.add("B");
    set.add("A");
}
```

호출할 때 구현체만 다르게 전달한다.

```text
addValues(new HashSet<>());
addValues(new LinkedHashSet<>());
addValues(new TreeSet<>());
```

이 코드를 통해 공통 기능은 `Set` 인터페이스로 사용하면서, 순서와 내부 동작은 구현체가 결정한다는 점을 확인할 수 있다.

---

## 8. HashSet의 크기 확장과 재해싱

해시 구조에 데이터가 계속 늘어나면 같은 인덱스에 값이 몰릴 가능성이 커진다.

버킷 하나에 값이 너무 많아지면 해당 버킷 안에서 비교해야 할 요소도 늘어난다.  
그러면 평균적으로 빠르던 검색 성능이 나빠질 수 있다.

Java의 `HashSet`은 내부 공간이 일정 수준 이상 차면 저장 공간을 늘리고, 기존 값의 인덱스를 새 크기에 맞춰 다시 계산한다.

이 과정을 재해싱이라고 한다.

```text
기존 배열 확장
→ 모든 요소의 해시 인덱스 재계산
→ 새 버킷에 다시 배치
```

기본적인 기준으로는 내부 공간의 약 75%가 사용되면 확장을 고려하는 구조를 학습했다.

재해싱 순간에는 여러 요소를 다시 배치하는 비용이 들지만, 이후 충돌을 줄여 평균 검색 성능을 유지하는 데 도움이 된다.

---

## 9. 구현체를 선택할 때 확인할 점

### HashSet을 선택할 때

- 출력 순서에 의존하지 않는가
- 중복 제거와 검색 속도가 중요한가

### LinkedHashSet을 선택할 때

- 중복 제거와 함께 입력 순서를 보여 줘야 하는가
- 순서 관리에 필요한 추가 비용을 감수할 수 있는가

### TreeSet을 선택할 때

- 정렬된 상태가 항상 필요할까
- 요소들이 서로 비교 가능한가
- `Comparator`로 별도 기준을 제공해야 하는가

Set을 쓴다는 사실만으로는 구현체가 정해지지 않는다.  
실제로 필요한 순서의 종류가 선택 기준이 된다.

---

## 핵심 정리

- `Set`은 중복 없는 요소 집합을 표현한다.
- `HashSet`은 순서를 보장하지 않지만 평균적으로 빠르다.
- `LinkedHashSet`은 요소가 추가된 순서를 유지한다.
- `TreeSet`은 값의 정렬 순서를 유지한다.
- 구현체는 “순서가 필요한가, 필요하다면 어떤 순서인가”를 기준으로 선택할 수 있다.
- 해시 구조는 데이터가 많아지면 공간을 확장하고 인덱스를 다시 계산해 충돌을 줄인다.
